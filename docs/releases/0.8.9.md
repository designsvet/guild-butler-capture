# Guild Butler Capture 0.8.9 — October compatibility hotfix

Candidate only: no public release has been authorized by preparing this branch.

## Member release notes

- Restores loot pickup and chest event recognition after the October Albion update.
- Fixes the incorrect character-stats decoder warning caused by renamed event numbers.
- Keeps the existing app, pairing and capture-folder format.

The update fixes future captures. It cannot recreate loot that the older decoder missed.
Windows receives the release through its existing updater; Mac users download the new DMG.

## Scope and evidence

This branch starts at public `v0.8.8` (`bf8a49dabeec7638ec72306ca0ee2d272157b3bb`),
not the later main/private app. The engine starts at the exact commit shipped in both
0.8.8 installers, `ab6cc6b181c62700b75d2ef34f47898145ba062a`, with only the October
event-table repair and its regressions. `resources/engine-lock.json` pins its reviewed
commit and the two changed runtime files. No private UI, combat, history, trades,
updater feeds or profile migrations are included.

The shipped engine drops the anonymized October 15 pickup on event 278 and misroutes
history event 143, producing eight character-stats failures. The corrected dispatcher
records the pickup once, accepts profile 142 and ignores history 143 without a warning.
The packaged-engine check repeats that scenario from the actual bundled source using
packaged Electron and requires the compiled capture binding to be present. On Mac it
also loads the native binding. On Windows that load check runs when Npcap is installed;
hosted runners without Npcap report the missing prerequisite explicitly. A green build
on such a runner does not establish Windows driver readiness.

Public 0.8.8's warning is in-memory and clears when the app exits. The persistent
decoder verdict and held-upload migration in private builds are not present here;
they must not be copied into this hotfix. The existing Stop-and-update behavior is retained.

## Review and release procedure

1. Review the engine and app maintenance PRs; require green engine tests, app tests,
   typechecking, layout checks and both platform packaging jobs.
2. Check the candidate on Windows and Apple Silicon with ordinary gameplay: detect the
   character after zoning, pick up loot, open a chest, stop capture, inspect the local file
   and verify paired guild upload. Current-client chest/fishing coverage still needs live
   confirmation; historical fixtures and CI alone do not prove it.
3. Obtain the owner's explicit public-release approval. Preparing/pushing these branches
   or building PR artifacts is not publication approval.
4. Merge the engine PR into `release/capture-0.8.x` without deleting the pinned commit.
   Merge the app PR into `release/0.8.x`. Verify both exact reviewed heads and the engine lock.
5. Only after approval, dispatch `capture-build` on `release/0.8.x` with
   `release_version=0.8.9`. Blank version is build-only; other branches cannot publish.
   The workflow never bumps or pushes main.
6. Verify the published Windows installer, `latest.yml` version/hash, stable download
   aliases and Mac DMG. Confirm Mac signing/notarization from the release build; PR
   packaging is not a substitute for Developer ID/Gatekeeper verification.

No public feed, existing release asset or installed app is modified during preparation.
Reconcile the engine repair into the later `protocol18` branch separately, accounting
for its additional journal/trade handlers before that branch is released.
