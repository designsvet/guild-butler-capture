# Guild Butler Capture 0.8.10 — usage sharing and support

Published for manual production testing as [v0.8.10-test.1](https://github.com/designsvet/guild-butler-capture/releases/tag/v0.8.10-test.1). The stable update feed remains on 0.8.9. The checklist below is the original preparation record; it does not assert that live-game acceptance is complete. Based on the public 0.8.9 maintenance release, with the same pinned October protocol repair (`2381fc7383ab4df7c08d729f1ef1d984c31c8685`). No v5/private renderer, art, trade or combat work is included.

## Member notes

- Optional usage and technical-health sharing helps us see whether capture is working. Choose on first launch or change it in Settings. Declining also stops the older automatic decoder-health report; local warnings remain visible.
- Settings → Report a bug lets you review and submit a report, optionally with a small diagnostic summary. It works even if you decline analytics or have not paired with Discord.
- Includes the October Albion compatibility fix from 0.8.9.

Stop capture before updating. Install over the existing app; do not uninstall or delete your application-data folder. Settings, pairing and saved captures should be preserved. Native acceptance below must confirm that behavior before release.

## Release gates

- [ ] Backend/Admin implementation is deployed and verified on staging.
- [ ] The actual candidate contains the pinned repaired engine and passes native packaged-engine verification.
- [ ] Windows 0.8.9 → 0.8.10 manual installation and automatic update preserve settings, encrypted pairing, saved captures and installation identity in a disposable profile.
- [ ] Mac 0.8.8/0.8.9 → 0.8.10 manual replacement preserves the same data in a disposable profile.
- [ ] Both clients complete real staging reports, consent changes and heartbeat checks.
- [ ] A Windows machine with Npcap and a Mac verify fresh Albion identity/zone, pickup and chest loot, local save and staging guild upload. Offline replay and CI packaging do not satisfy this gate.
- [ ] Privacy disclosure is published and the intended private health-alert destination is verified.
- [ ] Production backend and public release are explicitly authorized.

Only after authorization: merge the reviewed maintenance PR, dispatch `build.yml` on `release/0.8.x` with `release_version=0.8.10`, and verify published assets and updater hashes. Blank `release_version` produces test artifacts only. Never overwrite published 0.8.9 assets with different app bytes.
